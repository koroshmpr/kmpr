من هم مثل خیلی از توسعه‌دهنده‌های ایرانی کار را با وردپرس شروع کردم: قالب، افزونه، کمی PHP و بعد قالب اختصاصی. نقطه‌ای رسید که پروژه‌ها دیگر «سایت محتوایی» نبودند؛ قیمت‌هایی که هر چند ثانیه عوض می‌شدند، داشبوردی که هر کاربر چیز متفاوتی در آن می‌دید و صفحه‌هایی که باید به چند API وصل می‌شدند. آنجا بود که Next.js را جدی یاد گرفتم. این مقاله نقشه همان مسیر است: آموزش Next.js برای کسی که می‌خواهد بداند این فریم‌ورک کجا به درد کسب‌وکار می‌خورد، کجا نمی‌خورد و از کجا باید شروعش کرد.

این صفحه ستون دوره فرانت‌اند مدرن با React و Next.js است. هر بخش به یک درس کامل‌تر لینک می‌دهد؛ اگر عجله دارید، همین مقاله تصویر کلی را می‌دهد و بعد می‌توانید فقط درس‌هایی را بخوانید که لازم دارید.

Next.js دقیقاً چیست؟

React یک کتابخانه برای ساختن رابط کاربری از قطعه‌های کوچک به اسم کامپوننت است. React به‌تنهایی به شما نمی‌گوید صفحه‌ها چطور مسیر بگیرند، داده از کجا و کی خوانده شود، HTML کجا ساخته شود یا سایت چطور روی سرور اجرا شود. Next.js همین جاهای خالی را پر می‌کند: یک فریم‌ورک روی React که مسیریابی بر اساس پوشه‌ها، رندر سمت سرور، تولید صفحه ثابت، API داخلی، بهینه‌سازی تصویر و فونت و ابزار ساخت را یک‌جا می‌دهد.

تفاوت مهم با یک اپ React ساده این است که در Next.js صفحه می‌تواند روی سرور ساخته شود و HTML کامل به مرورگر برسد. یعنی موتور جست‌وجو و کاربر با اینترنت کند، محتوا را بدون منتظر ماندن برای اجرای کل جاوااسکریپت می‌بینند. این همان نقطه‌ای است که Next.js را برای سایت‌های تجاری، نه فقط پنل‌های داخلی، قابل استفاده می‌کند.

کی Next.js و کی وردپرس؟

این سؤالی است که بیشتر از همه از من می‌پرسند و جواب صادقانه‌اش این است که «بستگی دارد»، ولی نه به سلیقه؛ به نوع پروژه. خلاصه معیارهایی که خودم استفاده می‌کنم:

اشتباه رایج این است که Next.js را «نسخه بهتر وردپرس» بدانیم. این دو ابزار مسئله‌های متفاوتی را حل می‌کنند. اگر کارفرما هر روز مقاله و صفحه اضافه می‌کند و تیم فنی ندارد، Next.js بدون یک CMS پشت آن کار او را سخت‌تر می‌کند. اگر هم پروژه یک داشبورد معاملاتی است، تلاش برای ساختنش با افزونه‌های وردپرس معمولاً به سایتی کند و شکننده می‌رسد. برای ترکیب این دو، راهنمای وردپرس هدلس با Next.js را بخوانید و اگر هنوز بین قالب آماده، وردپرس اختصاصی و Next.js مردد هستید، مقایسه این سه گزینه در دوره طراحی سایت کمکتان می‌کند.

پیش‌نیازها: قبل از Next.js چه چیزهایی بلد باشیم؟

بزرگ‌ترین دلیل گیر کردن در یادگیری Next.js، شروع کردن از Next.js است. پیش‌نیازهایی که واقعاً لازم‌اند:

  • HTML و CSS درست: ساختار معنایی، Flexbox و Grid. اگر با Tailwind کار می‌کنید، باید بدانید هر کلاس چه CSSی می‌سازد.
  • جاوااسکریپت مدرن: const و let، توابع پیکانی، destructuring، ماژول‌ها (import/export)، Promise و async/await، و متدهای آرایه مثل map و filter.
  • مفاهیم HTTP: درخواست و پاسخ، کدهای وضعیت (۲۰۰، ۴۰۴، ۴۲۹، ۵۰۰)، هدرها و JSON.
  • React پایه: کامپوننت، props، state و رویدادها. این‌ها را در درس اول: ری‌اکت برای توسعه‌دهنده وردپرس توضیح داده‌ام.
  • کمی TypeScript: لازم نیست حرفه‌ای باشید، ولی تعریف نوع برای props و پاسخ API جلوی بخش بزرگی از باگ‌ها را می‌گیرد.

App Router: سایت از روی پوشه‌ها ساخته می‌شود

در Next.js مسیر هر صفحه از ساختار پوشه‌ها می‌آید. فایل app/page.tsx صفحه اصلی است، app/about/page.tsx صفحه «درباره ما» و app/blog/[slug]/page.tsx هر مقاله وبلاگ. فایل layout.tsx قالب مشترک صفحه‌ها (هدر، فوتر، فونت) را نگه می‌دارد و فایل‌هایی مثل loading.tsx، error.tsx و not-found.tsx حالت‌های بارگذاری، خطا و صفحه ۴۰۴ را مشخص می‌کنند.

app/
├─ layout.tsx          // هدر و فوتر مشترک
├─ page.tsx            // صفحه اصلی  →  /
├─ about/page.tsx      // →  /about
├─ blog/
│  ├─ page.tsx         // فهرست مقاله‌ها  →  /blog
│  └─ [slug]/page.tsx  // هر مقاله  →  /blog/nextjs-guide
└─ api/prices/route.ts // API داخلی  →  /api/prices

برای کسی که از وردپرس می‌آید، این ساختار شبیه سلسله‌مراتب قالب است، با این فرق که خودتان آن را می‌سازید و هیچ فایلی «جادویی» انتخاب نمی‌شود. جزئیات مسیرهای پویا، گروه‌بندی مسیرها، متادیتا و Route Handlerها در درس App Router و مسیریابی آمده است.

Server Component و Client Component

مهم‌ترین مفهوم Next.js جدید همین است و بیشتر سردرگمی‌ها از آن شروع می‌شود. در App Router همه کامپوننت‌ها به‌طور پیش‌فرض Server Component هستند: روی سرور اجرا می‌شوند، می‌توانند مستقیم از دیتابیس یا API بخوانند و جاوااسکریپت آن‌ها به مرورگر فرستاده نمی‌شود. هر جا به تعامل در مرورگر نیاز دارید، مثل دکمه، فرم با state یا تایمر، بالای فایل 'use client' می‌نویسید و آن کامپوننت Client Component می‌شود.

قاعده‌ای که به آن رسیده‌ام: صفحه را سرور بسازد و فقط «جزیره‌های» تعاملی در مرورگر اجرا شوند. اگر 'use client' را بالای کل صفحه بگذارید، عملاً مزیت Next.js را از دست داده‌اید و یک اپ React سنگین ساخته‌اید.

رندرینگ و کش: صفحه کی ساخته می‌شود؟

هر صفحه در Next.js یکی از این حالت‌ها را دارد:

  • ثابت (Static): یک بار هنگام build ساخته می‌شود و برای همه یکسان است؛ مثل صفحه «درباره ما».
  • بازسازی دوره‌ای (ISR): صفحه ثابت است ولی هر چند ثانیه یا با یک رویداد دوباره ساخته می‌شود؛ مثل فهرست مقاله‌ها.
  • پویا (Dynamic): برای هر درخواست ساخته می‌شود؛ مثل داشبورد کاربر یا صفحه‌ای که به کوکی وابسته است.

انتخاب درست بین این‌ها هم سرعت سایت را تعیین می‌کند و هم هزینه سرور را. قیمتی که هر ده ثانیه عوض می‌شود نباید یک ساعت در کش بماند و صفحه «درباره ما» هم نباید با هر بازدید دوباره ساخته شود. درس رندرینگ و کش در Next.js این تصمیم‌ها را با مثال توضیح می‌دهد.

اتصال به API و داده زنده

جایی که Next.js بیشترین ارزش را نشان می‌دهد، کار با داده بیرونی است. چند اصل که در پروژه‌های قیمت زنده یاد گرفتم:

  • کلید API هرگز به مرورگر نمی‌رسد؛ درخواست از سرور (Server Component یا Route Handler) زده می‌شود.
  • هر منبع داده نرخ مجاز درخواست دارد. اگر هر بازدیدکننده مستقیم API بیرونی را صدا بزند، دیر یا زود خطای ۴۲۹ می‌گیرید؛ پس پاسخ را در سرور کش کنید.
  • فرمت پاسخ API بدون خبر عوض می‌شود. پاسخ را قبل از استفاده اعتبارسنجی کنید تا به‌جای صفحه سفید، پیام خطای قابل‌فهم یا آخرین داده سالم نمایش داده شود.
  • برای هر داده مشخص کنید چقدر «کهنه» قابل قبول است و کش را با همان عدد تنظیم کنید.

این الگوها با کد در درس اتصال Next.js به API و داده زنده آمده‌اند. اگر سمت وردپرس هم API می‌سازید، درس REST API وردپرس و یکپارچه‌سازی مکمل آن است.

سئو در Next.js

Next.js به‌خاطر رندر سمت سرور برای سئو مناسب است، ولی سئو را خودکار انجام نمی‌دهد. چیزهایی که باید خودتان بسازید:

  • عنوان و توضیحات هر صفحه با metadata یا generateMetadata.
  • آدرس canonical، نقشه سایت (app/sitemap.ts) و robots.ts.
  • داده ساختاریافته JSON-LD برای مقاله، محصول یا سؤالات متداول؛ الگوهایش در راهنمای اسکیما آمده است.
  • ریدایرکت ۳۰۱ آدرس‌های قدیمی وقتی از وردپرس مهاجرت می‌کنید؛ بدون آن رتبه‌های قبلی از دست می‌روند.

دیپلوی: سایت Next.js کجا اجرا شود؟

وردپرس روی تقریباً هر هاست اشتراکی اجرا می‌شود، ولی Next.js برای بخش‌های پویا به Node.js نیاز دارد. برای کسب‌وکارهای ایرانی معمولاً این گزینه‌ها مطرح است: سرور مجازی با Node.js و یک مدیر فرایند، کانتینر Docker، سرویس‌های ابری داخلی که از Node پشتیبانی می‌کنند، یا خروجی کاملاً ثابت (static export) برای سایت‌هایی که بخش پویا ندارند. سرویس‌های خارجی مثل Vercel راحت‌اند، ولی قبل از انتخابشان دسترسی کاربران ایرانی، روش پرداخت و جای داده‌ها را بسنجید. جزئیات در درس دیپلوی Next.js روی سرور آمده است.

هوش مصنوعی: شتاب‌دهنده، نه جایگزین فهم

بخش بزرگی از سرعت امروز من در ساختن اپ‌ها از ابزارهای هوش مصنوعی می‌آید، ولی فقط به این دلیل که کدی را که تولید می‌کنند می‌فهمم و بازبینی می‌کنم. هوش مصنوعی خیلی راحت 'use client' را بالای همه‌چیز می‌گذارد، کلید API را در کد سمت مرورگر می‌نویسد یا از الگوهای نسخه‌های قدیمی Next.js استفاده می‌کند. روش کار و چک‌لیست بازبینی من در درس هوش مصنوعی در برنامه‌نویسی وب آمده است.

جمع‌بندی

Next.js ابزار درستی برای پروژه‌هایی است که داده زنده، منطق پیچیده یا تجربه اپ‌مانند دارند و برای سایت‌های محتوایی ساده لزوماً بهتر از وردپرس نیست. اگر React پایه را بلدید، با فهم سه مفهوم (مسیریابی با پوشه‌ها، مرز Server و Client Component و استراتژی کش) بیشترین بخش راه را رفته‌اید و بقیه تمرین است.

اگر برای کسب‌وکارتان وب‌اپ، داشبورد یا سایتی با داده زنده لازم دارید و نمی‌دانید Next.js انتخاب درستی است یا وردپرس، فرم درخواست پروژه را پر کنید تا با هم بررسی کنیم.
