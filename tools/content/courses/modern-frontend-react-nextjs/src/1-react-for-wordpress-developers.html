وقتی از وردپرس به React آمدم، سخت‌ترین بخش سینتکس نبود؛ عوض کردن طرز فکر بود. در PHP صفحه را از بالا به پایین می‌سازید و تمام. در React رابط کاربری «تابعی از داده» است: داده عوض می‌شود و React خودش تصمیم می‌گیرد کدام قسمت صفحه دوباره ساخته شود. در این درس آموزش ری‌اکت را از همان زاویه‌ای شروع می‌کنم که برای یک توسعه‌دهنده وردپرس آشناست.

این درس اول دوره آموزش Next.js برای کسب‌وکار است. اگر React را بلدید، مستقیم به درس App Router بروید.

کامپوننت: همان template-part، ولی با ورودی مشخص

در قالب وردپرس با get_template_part() یک تکه از صفحه را جدا می‌کنید و با آرگومان سوم داده به آن می‌دهید. کامپوننت React همین ایده است، با این فرق که یک تابع جاوااسکریپت است که JSX برمی‌گرداند:

سه نکته که تازه‌کارها معمولاً جا می‌اندازند:

  • نام کامپوننت با حرف بزرگ شروع می‌شود؛ priceCard به‌عنوان تگ HTML ناشناخته تفسیر می‌شود.
  • در JSX به‌جای class از className و به‌جای for از htmlFor استفاده می‌شود.
  • هر چیزی داخل {} عبارت جاوااسکریپت است. if مستقیم داخل JSX کار نمی‌کند؛ از عملگر سه‌تایی یا && استفاده کنید.

props: داده از بالا به پایین

props ورودی‌های کامپوننت‌اند و فقط‌خواندنی هستند. کامپوننت فرزند نباید props را تغییر دهد؛ اگر داده باید عوض شود، صاحب آن داده (کامپوننت والد) تغییرش می‌دهد. این قاعده «جریان یک‌طرفه داده» است و دلیل اینکه اپ‌های React با بزرگ شدن قابل‌فهم می‌مانند.

با TypeScript نوع props را تعریف کنید. هزینه‌اش چند خط است و در عوض اگر جایی price را به‌صورت رشته بفرستید، قبل از اجرا خطا می‌گیرید، نه وقتی کاربر عدد اشتباه می‌بیند.

state: داده‌ای که کامپوننت خودش نگه می‌دارد

چند قاعده که خیلی از باگ‌ها را حذف می‌کند:

  • state را مستقیم تغییر ندهید (count++ یا items.push())؛ همیشه با تابع set و یک مقدار جدید.
  • وقتی مقدار جدید به مقدار قبلی وابسته است، از شکل تابعی استفاده کنید: setCount((c) => c + 1).
  • چیزی را که می‌شود از state یا props محاسبه کرد، در state جدا نگه ندارید. مثلاً جمع سبد خرید را از فهرست اقلام حساب کنید.
  • 'use client' در Next.js لازم است، چون state فقط در مرورگر معنا دارد.

useEffect: کمتر از آنچه فکر می‌کنید

useEffect برای همگام شدن با چیزی بیرون از React است: تایمر، اتصال WebSocket یا گوش دادن به رویداد پنجره. اشتباه رایج، استفاده از آن برای دریافت داده اولیه صفحه یا محاسبه یک مقدار از state است. در Next.js داده اولیه را در Server Component بخوانید و مقدارهای مشتق‌شده را مستقیم هنگام رندر حساب کنید.

useEffect(() => {
  const id = setInterval(refresh, 30_000);
  return () => clearInterval(id); // پاک‌سازی: بدون آن با هر رندر یک تایمر جدید اضافه می‌شود
}, []);

تابعی که از effect برمی‌گردد پاک‌سازی است. هر effectی که چیزی را «روشن» می‌کند (تایمر، اتصال، listener) باید آن را خاموش هم بکند.

استایل‌دهی: Tailwind و دیزاین سیستم کوچک

اگر در وردپرس با Tailwind کار کرده‌اید، در React هم همان کلاس‌ها را می‌نویسید. تفاوت این است که حالا کامپوننت‌ها خودشان واحد دیزاین سیستم‌اند: یک Button با چند حالت مشخص، به‌جای کپی کردن ده کلاس روی هر دکمه. قاعده من این است که هر الگویی که سه بار تکرار شد، کامپوننت شود. گردش کار ساخت Tailwind را در درس گردش کار مدرن وردپرس با Tailwind و esbuild از دوره وردپرس توضیح داده‌ام.

جمع‌بندی

React بر چند ایده ساده بنا شده: کامپوننت‌های کوچک، props فقط‌خواندنی، state حداقلی و رابط کاربری‌ای که از داده ساخته می‌شود. اگر این‌ها را درست جا بیندازید، Next.js فقط لایه‌ای است که مشخص می‌کند کدام کامپوننت روی سرور و کدام در مرورگر اجرا شود.

درس بعدی، App Router در Next.js، این کامپوننت‌ها را به صفحه و مسیر تبدیل می‌کند. برای نقشه کامل دوره به راهنمای Next.js برای کسب‌وکار برگردید.

اگر پنل یا وب‌اپی لازم دارید که روی React ساخته شود، فرم درخواست پروژه را پر کنید.
