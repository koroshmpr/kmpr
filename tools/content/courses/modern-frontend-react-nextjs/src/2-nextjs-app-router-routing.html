اولین باری که پروژه Next.js را باز کردم، دنبال فایلی می‌گشتم که «آدرس‌ها» را تعریف کند؛ چیزی شبیه تنظیمات پیوندهای یکتا در وردپرس. چنین فایلی وجود ندارد. در App Router در Next.js خود پوشه‌ها آدرس‌اند و چند نام فایل رزروشده تعیین می‌کنند هر آدرس چه چیزی نمایش بدهد. این درس همه آن‌ها را با یک مثال واقعی (سایتی با صفحه اصلی، وبلاگ و API قیمت) توضیح می‌دهد.

این درس دوم دوره آموزش Next.js برای کسب‌وکار است و فرض می‌کند مفاهیم پایه React را می‌دانید.

قاعده اصلی: پوشه = بخش آدرس، page = صفحه

هر پوشه داخل app/ یک بخش از آدرس است، ولی فقط وقتی فایل page.tsx داشته باشد آن آدرس قابل بازدید می‌شود. یعنی می‌توانید پوشه‌ای برای نگه داشتن کامپوننت‌ها داشته باشید بدون اینکه آدرس عمومی بسازد.

app/
├─ layout.tsx              // ریشه: html، body، هدر و فوتر
├─ page.tsx                // /
├─ about/page.tsx          // /about
├─ blog/
│  ├─ page.tsx             // /blog
│  └─ [slug]/
│     ├─ page.tsx          // /blog/هر-مقاله
│     └─ loading.tsx       // اسکلت بارگذاری مقاله
├─ (marketing)/
│  └─ webinar/page.tsx     // /webinar  — پرانتز در آدرس نمی‌آید
├─ api/prices/route.ts     // /api/prices
└─ not-found.tsx           // صفحه ۴۰۴ سفارشی

فایل‌های رزروشده‌ای که بیشتر از همه استفاده می‌شوند:

  • page.tsx: محتوای خود صفحه.
  • layout.tsx: قالبی که دور صفحه‌های آن پوشه و زیرپوشه‌ها می‌پیچد و هنگام جابه‌جایی بین آن‌ها دوباره ساخته نمی‌شود.
  • loading.tsx: چیزی که تا آماده شدن صفحه نمایش داده می‌شود.
  • error.tsx: رابط خطا برای آن بخش؛ باید Client Component باشد.
  • not-found.tsx: صفحه وقتی محتوا پیدا نشد.
  • route.ts: پاسخ‌دهنده API به‌جای صفحه.

مسیرهای پویا: [slug] و generateStaticParams

پوشه‌ای که نامش داخل کروشه است، بخش متغیر آدرس را می‌گیرد. در صفحه مقاله، مقدار slug از params خوانده می‌شود:

// app/blog/[slug]/page.tsx
import { notFound } from 'next/navigation';
import { getPost, getAllSlugs } from '@/lib/posts';

export async function generateStaticParams() {
  const slugs = await getAllSlugs();
  return slugs.map((slug) => ({ slug }));
}

export default async function PostPage({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params;
  const post = await getPost(slug);
  if (!post) notFound();
  return 
{post.title}
{/* ... */}
;
}

در نسخه‌های جدید Next.js، params یک Promise است و باید await شود؛ اگر مثال‌های قدیمی را کپی کنید، این تفاوت را ببینید. generateStaticParams به Next.js می‌گوید کدام مقاله‌ها را هنگام build بسازد. اگر بعداً مقاله جدیدی اضافه شود، بسته به تنظیمات کش در اولین درخواست ساخته می‌شود؛ این را در درس رندرینگ و کش توضیح داده‌ام.

چند شکل دیگر مسیر پویا:

  • [...slug] همه بخش‌های بعدی را می‌گیرد؛ مثلاً /docs/a/b/c.
  • [[...slug]] همان است ولی آدرس بدون بخش اضافه را هم پوشش می‌دهد.

گروه‌بندی مسیرها و پوشه‌های خصوصی

پوشه‌ای که نامش داخل پرانتز است، مثل (marketing)، در آدرس ظاهر نمی‌شود. از آن برای دو کار استفاده می‌کنم: مرتب کردن فایل‌ها و دادن layout جدا به یک گروه صفحه. مثلاً صفحه‌های لندینگ کمپین بدون هدر و فوتر اصلی، و صفحه‌های داشبورد با منوی کناری.

پوشه‌ای که با زیرخط شروع شود، مثل _components، اصلاً مسیر نمی‌سازد و جای خوبی برای کامپوننت‌هایی است که فقط همان بخش استفاده می‌کند.

لینک و جابه‌جایی بین صفحه‌ها

برای لینک داخلی از Link استفاده کنید، نه تگ a ساده. Link صفحه مقصد را بدون بارگذاری کامل عوض می‌کند و لینک‌هایی را که در دید کاربر هستند از قبل آماده می‌کند:

import Link from 'next/link';

{post.title}

خروجی Link همچنان یک تگ a واقعی با href است، پس برای موتور جست‌وجو قابل خزش است. برای جابه‌جایی از داخل کد، مثلاً بعد از ثبت فرم، از useRouter در Client Component یا redirect در سمت سرور استفاده می‌شود.

متادیتا و سئو هر صفحه

عنوان و توضیحات ثابت با export const metadata و عنوان وابسته به داده با generateMetadata ساخته می‌شود:

export async function generateMetadata({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params;
  const post = await getPost(slug);
  return {
    title: post?.seoTitle ?? 'مقاله',
    description: post?.excerpt,
    alternates: { canonical: `/blog/${slug}` },
    openGraph: { images: post?.cover ? [post.cover] : [] },
  };
}

Next.js درخواست‌های تکراری fetch با آدرس و تنظیمات یکسان را در یک رندر یک بار اجرا می‌کند، پس خواندن مقاله هم در generateMetadata و هم در صفحه دو درخواست به API نمی‌زند. اگر داده را مستقیم از دیتابیس می‌خوانید، تابع را با cache از React بپیچید تا همین رفتار را داشته باشد. نقشه سایت هم با فایل app/sitemap.ts ساخته می‌شود. چک‌لیست کامل سئو داخلی را در چک‌لیست سئو داخلی از دوره سئو ببینید.

Route Handler: API داخل همان پروژه

فایل route.ts به‌جای صفحه، پاسخ HTTP برمی‌گرداند. برای فرم‌ها، وب‌هوک‌ها و پراکسی کردن APIهای بیرونی (تا کلید API در مرورگر دیده نشود) از آن استفاده می‌کنم:

// app/api/leads/route.ts
import { NextResponse } from 'next/server';

export async function POST(req: Request) {
  const body = await req.json().catch(() => null);
  const phone = typeof body?.phone === 'string' ? body.phone : '';
  if (!/^09\d{9}$/.test(phone)) {
    return NextResponse.json({ error: 'شماره نامعتبر است' }, { status: 422 });
  }
  await saveLead(phone); // ذخیره یا ارسال به CRM
  return NextResponse.json({ ok: true }, { status: 201 });
}

هر متد HTTP یک تابع جدا با همان نام است (GET، POST و غیره). همان قواعد امنیتی REST API وردپرس اینجا هم صدق می‌کند: ورودی را اعتبارسنجی کنید، کد وضعیت درست برگردانید و برای مسیرهای عمومی محدودیت نرخ بگذارید.

جمع‌بندی

App Router با چند قاعده ساده کار می‌کند: پوشه‌ها آدرس‌اند، page صفحه را می‌سازد، layout قالب مشترک را نگه می‌دارد، کروشه یعنی بخش پویا، پرانتز یعنی گروه بدون آدرس و route.ts یعنی API. اگر این ساختار را از اول درست بچینید، اضافه کردن بخش‌های جدید به پروژه ساده می‌ماند.

درس قبل ری‌اکت برای توسعه‌دهنده وردپرس بود. در درس بعد، رندرینگ و کش در Next.js، می‌بینیم هر کدام از این صفحه‌ها کی و کجا ساخته می‌شوند. برای نقشه کامل دوره به راهنمای Next.js برگردید.

اگر می‌خواهید سایت یا وب‌اپتان با Next.js و ساختاری قابل توسعه ساخته شود، فرم درخواست پروژه را پر کنید.
