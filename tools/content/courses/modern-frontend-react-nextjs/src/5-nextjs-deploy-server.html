ساختن پروژه Next.js روی لپ‌تاپ یک چیز است و اجرای پایدارش روی سرور چیز دیگر. وردپرس را تقریباً روی هر هاست اشتراکی می‌شود بالا آورد، ولی Next.js برای بخش‌های پویا یک پردازش Node.js می‌خواهد که همیشه روشن بماند، بعد از خطا دوباره بالا بیاید و پشت یک وب‌سرور قرار بگیرد. در این درس روشی را توضیح می‌دهم که برای دیپلوی Next.js روی سرور مجازی استفاده می‌کنم، به‌همراه گزینه‌های دیگر و معیار انتخاب بینشان.

این درس پنجم دوره آموزش Next.js برای کسب‌وکار است و بعد از درس اتصال به API می‌آید.

اول تصمیم بگیرید: سایت شما واقعاً سرور لازم دارد؟

اگر سایت هیچ بخش پویایی ندارد (نه Route Handler، نه صفحه وابسته به کوکی، نه ISR)، می‌توانید با output: 'export' خروجی کاملاً ثابت بگیرید و پوشه out را روی هر هاست یا CDN بگذارید. ساده‌ترین و ارزان‌ترین حالت است.

به محض اینکه API داخلی، فرم سمت سرور، داده زنده یا بازسازی صفحه دارید، به پردازش Node.js نیاز است. گزینه‌ها:

گزینهمزیتچیزی که باید بسنجید
سرور مجازی + Node.js + PM2کنترل کامل، هزینه قابل پیش‌بینینگهداری سرور، به‌روزرسانی و امنیت با خود شماست
Docker روی سرور مجازیمحیط یکسان در توسعه و تولید، جابه‌جایی آسانکمی پیچیدگی بیشتر در شروع
سرویس ابری داخلی با پشتیبانی Node.jsبدون نگهداری سرور، دسترسی خوب برای کاربران ایرانمحدودیت‌های سرویس و هزینه با رشد ترافیک
سرویس‌های خارجی مثل Vercelساده‌ترین تجربه دیپلویدسترسی کاربران ایرانی، روش پرداخت، محل نگهداری داده و وابستگی به سرویس خارجی

خروجی standalone: سبک‌ترین بسته برای سرور

با تنظیم output: 'standalone'، Next.js هنگام build یک پوشه می‌سازد که فقط فایل‌ها و وابستگی‌های لازم برای اجرا را دارد. لازم نیست کل node_modules را روی سرور نصب کنید:

// next.config.ts
import type { NextConfig } from 'next';

const nextConfig: NextConfig = {
  output: 'standalone',
  poweredByHeader: false,
};
export default nextConfig;

بعد از next build، پوشه .next/standalone شامل یک server.js است. دو پوشه را باید کنارش کپی کنید، چون به‌طور خودکار داخلش نیستند: public و .next/static.

cp -r public .next/standalone/
cp -r .next/static .next/standalone/.next/
node .next/standalone/server.js   # روی پورت 3000

همیشه روشن: PM2

اگر پردازش Node را مستقیم اجرا کنید، با بسته شدن ترمینال یا اولین خطای جدی، سایت می‌خوابد. PM2 پردازش را مدیریت می‌کند، بعد از خطا دوباره بالا می‌آورد و بعد از ری‌استارت سرور هم اجرایش می‌کند:

// ecosystem.config.js
module.exports = {
  apps: [{
    name: 'site',
    script: '.next/standalone/server.js',
    env: { NODE_ENV: 'production', PORT: 3000, HOSTNAME: '127.0.0.1' },
    max_memory_restart: '600M',
  }],
};
pm2 start ecosystem.config.js
pm2 save && pm2 startup   # اجرا بعد از ری‌استارت سرور
pm2 logs site             # دیدن لاگ‌ها

HOSTNAME: '127.0.0.1' باعث می‌شود Node فقط از داخل خود سرور در دسترس باشد و ترافیک بیرونی فقط از مسیر Nginx برسد.

Nginx جلوی Node.js

Nginx گواهی SSL، فشرده‌سازی، کش فایل‌های ثابت و محدودیت نرخ را مدیریت می‌کند و درخواست‌ها را به Node می‌رساند:

server {
    listen 443 ssl http2;
    server_name example.ir;
    # ssl_certificate ... ; ssl_certificate_key ... ;

    location /_next/static/ {
        alias /var/www/site/.next/standalone/.next/static/;
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

فایل‌های داخل /_next/static/ نام هش‌شده دارند و با هر build عوض می‌شوند؛ برای همین می‌شود آن‌ها را یک سال کش کرد. صفحه‌ها را با این کش طولانی سرو نکنید.

Docker: وقتی محیط یکسان مهم است

اگر چند سرور یا چند نفر در تیم دارید، Docker تضمین می‌کند نسخه Node و وابستگی‌ها همه‌جا یکی باشد. یک Dockerfile چندمرحله‌ای ساده:

FROM node:22-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:22-alpine
WORKDIR /app
ENV NODE_ENV=production
COPY --from=build /app/.next/standalone ./
COPY --from=build /app/.next/static ./.next/static
COPY --from=build /app/public ./public
EXPOSE 3000
CMD ["node", "server.js"]

در سرورهای داخل ایران، دسترسی به مخزن‌های رسمی Docker و npm ممکن است محدود یا کند باشد. یا build را در CI بیرون از سرور انجام دهید و فقط ایمیج یا خروجی نهایی را منتقل کنید، یا از میرورهای داخلی معتبر استفاده کنید.

متغیرهای محیطی در تولید

  • متغیرهای NEXT_PUBLIC_ هنگام build داخل کد قرار می‌گیرند؛ تغییرشان روی سرور بدون build دوباره اثری ندارد.
  • متغیرهای سمت سرور (کلیدها، آدرس دیتابیس) هنگام اجرا خوانده می‌شوند و در PM2 یا Docker تعریف می‌شوند.
  • فایل .env تولید را در git نگذارید و دسترسی خواندنش روی سرور را محدود کنید.

دیپلوی خودکار با GitHub Actions

دیپلوی دستی با SSH دیر یا زود یک مرحله را جا می‌اندازد. گردش کاری که استفاده می‌کنم: با هر push به شاخه اصلی، CI وابستگی‌ها را نصب می‌کند، lint و build را اجرا می‌کند و اگر همه موفق بود، خروجی را به سرور می‌فرستد و PM2 را با pm2 reload بدون قطعی دوباره بالا می‌آورد. همان منطق دیپلوی خودکاری که در گردش کار مدرن وردپرس برای قالب وردپرس توضیح داده‌ام، اینجا هم صدق می‌کند: build در CI، نه روی سرور تولید.

دو نکته که از تجربه یاد گرفتم: نسخه قبلی را نگه دارید تا در صورت مشکل با یک دستور برگردید، و بعد از هر دیپلوی یک درخواست ساده به صفحه اصلی و مسیر سلامت بزنید تا اگر سایت بالا نیامده، همان لحظه بفهمید.

امنیت و نگهداری بعد از دیپلوی

  • Next.js و وابستگی‌ها را مرتب به‌روز کنید؛ هشدارهای امنیتی فریم‌ورک را دنبال کنید.
  • هدرهای امنیتی (CSP، HSTS، X-Content-Type-Options) را در Nginx یا next.config تنظیم کنید.
  • برای Route Handlerهای عمومی در Nginx محدودیت نرخ بگذارید.
  • لاگ‌ها را بچرخانید (log rotation) تا دیسک سرور پر نشود.
  • از سرور و دیتابیس بکاپ منظم بگیرید و ریستور را تست کنید.

بیشتر این موارد بین وردپرس و Next.js مشترک‌اند؛ نسخه کاملشان در راهنمای امنیت و نگهداری سایت آمده است.

جمع‌بندی

اگر سایت بخش پویا ندارد، خروجی ثابت بگیرید. اگر دارد، الگوی قابل‌اعتماد این است: build با standalone در CI، اجرا با PM2 یا Docker، Nginx جلوی آن برای SSL و فایل‌های ثابت، و دیپلوی خودکار با امکان برگشت. انتخاب بین سرور خودتان و سرویس‌های آماده را بر اساس دسترسی کاربران، هزینه و توان نگهداری تیمتان انجام دهید.

درس قبل اتصال Next.js به API بود. درس پایانی دوره، هوش مصنوعی در برنامه‌نویسی وب، درباره سریع‌تر ساختن همه این‌ها بدون فدا کردن کیفیت است. نقشه دوره در راهنمای Next.js است.

اگر پروژه Next.js دارید و برای راه‌اندازی یا نگهداری پایدارش روی سرور کمک می‌خواهید، فرم درخواست پروژه را پر کنید.
